Why this file exists (BLD-2586)
-------------------------------
The visual-audit harness runs Chromium in a *fontless* agent-runtime
container (no /usr/share/fonts, no fontconfig). With no system text font,
Chromium measures every sans/serif text run as 0x0, so ALL app text
vanishes from audit screenshots and the audit emits a whole class of false
"missing text/label" findings.

scripts/inject-audit-fonts.mjs base64-inlines THIS file into the served
dist/index.html as a blocking FontFace() loader, aliased to the concrete
family names in react-native-web's default font stack
(-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial),
so text renders and the audit can validate it.

IMPORTANT — this font is E2E-ONLY and is NEVER shipped in the app:
  * It lives under e2e/ (not under public/ or assets/), so `expo export`
    does not bundle it.
  * It is never imported by app code.
  * The injector is gated behind a font-presence probe: it is a no-op on
    any host that already has /usr/share/fonts (e.g. CI's ubuntu-latest),
    so CI audit screenshots are byte-for-byte unchanged.

To refresh this asset, re-download the latin-subset WOFF2 from the Google
Fonts css2 URL above (send a modern-browser User-Agent so woff2 is served),
update the File URL + sha256 here, and re-run the E2E audit-font spec.
