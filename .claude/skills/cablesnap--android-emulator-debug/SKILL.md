# Vision — the agent's eyes (VL model)
The driving agent CANNOT view images. Use a local Ollama vision-language model as its eyes.
- `scripts/look.sh <label> "<question>"` screenshots the emulator, sends the PNG to the VL model, and prints BOTH a text description AND tappable `(x,y) 'label'` bounds (from uiautomator).
- Vision models present locally: `qwen3-vl:8b` (~5s, default, fine for navigation-state detection) and `qwen3-vl:32b` (~30s, use for fine detail). Override with `VL_MODEL=`.
- Drive ONE tap at a time: `look.sh` -> read description + bounds -> `adb shell input tap X Y` -> `look.sh` again. NEVER blind-chain taps.
- The VL model is UNRELIABLE at tiny resolutions (e.g. judging whether a small grid thumbnail is a real frame vs a placeholder), and can flip its answer between reads. For fine visual judgments do NOT trust a full-screen read -- get ground truth from the filesystem/logcat (below), or crop+upscale the region (`magick in.png -crop WxH+X+Y -resize 400x400 out.png`) and re-read with `qwen3-vl:32b`.

# On-device evidence (don't trust pixels alone)
Prefer hard evidence over a VL screenshot read when verifying a feature:
- App sandbox files: `adb shell run-as com.persoack.cablesnap find . -type f` -- inspect what the app actually wrote. Pull one: `adb exec-out run-as com.persoack.cablesnap cat <relpath> > /tmp/x`.
- logcat after each step: `adb logcat -d | grep -iE '<feature-keywords>|fatal|exception' | tail -50`. Absence of logs proves nothing if the code has no logging -- treat as a non-signal, not a failure.
- To judge a file's visual content, pull it and feed the FILE (not a screen crop) to `qwen3-vl:32b` via the Ollama `/api/generate` `images` array.

# Form clips (video thumbnails + playback) -- verified reference
Form clips are short videos bound to an exercise. Facts confirmed on-device:
- Clip videos: `files/form-clips/<gym-profile-id>/<uuid>.mp4` in the app sandbox (e.g. `files/form-clips/voltra-001/<uuid>.mp4`).
- Thumbnails: generated by `lib/media/form-clip-thumbs.ts` `getOrCreateThumb(clipId, relPath)` (expo-video-thumbnails), cached at `cache/form-clip-thumbs/<clipId>.jpg` (a real ~12 KB JPEG frame -- NOT stored beside the .mp4). A real JPEG file = success; missing = generation failed.
- Playback: expo-video (ExoPlayer). Confirm real playback in logcat: `adb logcat -d | grep -iE 'ExoPlayer|MediaSessionService|PLAYING' | tail` -- a working stream shows `playbackState=PLAYING(3)` with `position=` advancing each second.
- Record path: exercise detail slide-sheet -> "Form clips" tab -> "Record" -> "Start recording" -> "Save clip" (grant camera+mic if prompted; 15s max). The emulator VIRTUAL camera outputs a synthetic test scene, so recorded frames/thumbnails look like abstract colored blocks (stylized 3D render), NOT gym footage -- expected; a physical device shows real frames.
- Two surfaces share the same player (components/session/FormClipsPlayer.tsx) + thumbnail component (components/session/ClipThumbImage.tsx): (1) exercise detail Form clips tab (FormLibraryTab.tsx), (2) Settings -> "Manage form clips" (FormClipsManageSheet.tsx).
