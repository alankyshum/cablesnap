CableSnap i18n Rollout — Lingui v6, 4 locales, local-ollama pipeline

Generated: 2026-08-17

Goal

Ship user-selectable language (en-US default, plus en-GB, zh-TW, zh-CN) across all UI chrome, with a zero-cost local-ollama translation step wired into the pre-push/CI gate and a runnable per-route-per-locale coverage check.

Assumptions

  • Stack is LOCKED (do not re-litigate): Lingui v6 (@lingui/core+react+cli+babel-plugin-lingui-macro 6.6.0), expo-localization (already a dep at package.json:71), @formatjs/intl-pluralrules + getcanonicallocales + locale polyfills.
  • Authoring form is LOCKED: explicit-id macros `<Trans id="k">Source</Trans>` and `t({id, message})`. No auto-generated hash ids.
  • Catalog layout is LOCKED (REVISED by D4): locales/en-US.json is the FULL source; locales/zh-TW.json is FULL; locales/en-GB.json is PARTIAL (divergent keys only, absence = inherit); locales/zh-CN.json is a COMMITTED GENERATED artifact that is FULL by construction and never hand-edited; locales/zh-CN.overrides.json is the hand-authored PARTIAL file. Runtime fallback chains: en-GB→en-US, zh-TW→en-US, zh-CN→en-US. zh-TW is a BUILD-time input to zh-CN, NOT a runtime fallback for it.
  • Entry shape is LOCKED: {message, srcHash: sha256(key+\0+source)[0:12], origin: "machine"|"human"}. Never re-translate an entry whose srcHash matches or whose origin is "human".
  • Translator is LOCKED: local ollama is the DEFAULT and only required path (model per D1 below); gpt-4o-mini is an optional adapter behind the same interface. The translate script is dev-only and MUST NOT be bundled (F-Droid/FOSS constraint).
  • COST DESIGN (planner decision, conservative): the gate (`scripts/check-i18n-gate.ts --check`) is pure/offline and never calls an LLM, so CI cost is exactly zero and no model credentials enter CI. Translation is an explicit LOCAL command (`npm run i18n:translate`) that a dev runs when the gate reports staleness. This is the cheapest reading of 'translate in the merge pipeline, best if run locally'.
  • COLLISION DESIGN (planner decision): Wave-4 migration agents NEVER hand-edit locales/*.json. They edit .tsx/.ts sources only; the source catalog is regenerated once, serially, by `lingui extract` in T13. This is what makes 6 concurrent batches safe.
  • Repo conventions to mirror: gate script shape and exit codes follow scripts/check-changelog-gate.ts (pure exported fns + main() + process.exit); pre-push wiring follows the `if [ -f "scripts/X.ts" ]; then npx tsx scripts/X.ts; fi` block pattern in .husky/pre-push:64-69.
  • Verified npm scripts available for VERIFY steps: `npm run typecheck` (tsc --noEmit), `npm run lint`, `npm test`, `npm run test:e2e` (playwright).
  • ALL PLANNING DECISIONS ARE RESOLVED — D1 through D5 are settled and recorded below as DECIDED assumptions. The Open Decisions section is empty by design; nothing in this plan is waiting on a human choice.
  • DECIDED (D1) — ollama model: the default is `qwen3:14b`, but it MUST be read from the `I18N_OLLAMA_MODEL` environment variable with `qwen3:14b` as the fallback default. The model name is never hardcoded at a call site.
  • DECIDED (D2) — the literal-string lint rule is WARN-ONLY and must never fail CI. RATIONALE: the generated MessageKey union already hard-blocks unknown keys at typecheck time, so a no-literal rule adds high noise for no additional safety.
  • DECIDED (D3) — en-GB diverges from en-US on SPELLING (-ise/-isation, colour, metre) and FITNESS VOCABULARY only. It does NOT diverge on date or number phrasing: locale-aware formatting is already Out of Scope for this plan.
  • DECIDED (D4) — zh-CN is GENERATED, not partial. locales/zh-CN.json = opencc Traditional→Simplified conversion of locales/zh-TW.json (opencc-js config tw2sp, i.e. the reverse of s2twp), merged over locales/zh-CN.overrides.json; overrides always win. zh-CN.overrides.json is the ONLY human-authored zh-CN file and holds ONLY hand-declared lexical divergences (影片/视频, 程式/程序). RATIONALE — this SUPERSEDES the earlier zh-CN→zh-TW→en-US partial-catalog design, which was a defect: any key absent from a partial zh-CN would have rendered TRADITIONAL characters to mainland users. A full generated catalog makes that structurally impossible.
  • DECIDED (D4, gate contract) — the gate enforces the generated-artifact invariant: regenerating locales/zh-CN.json from zh-TW + zh-CN.overrides.json must produce a BYTE-IDENTICAL file, else fail `I18N_ZHCN_STALE`; and an entry in zh-CN.overrides.json that equals what opencc tw2sp would already produce fails `I18N_REDUNDANT_OVERRIDE`. opencc-js is a pure local library, so the gate stays offline and zero-cost.
  • DECIDED (D5) — seed/curated-program/foods data localization is DEFERRED; T18 records the boundary and the actionable follow-up shape. No change to T18's scope.

Success Criteria

  • Settings exposes a Language picker with en-US, en-GB, zh-TW, zh-CN; selection applies immediately and survives a cold start; unset resolves to en-US.
  • `npm run test:e2e -- e2e/i18n-coverage.spec.ts` passes, asserting every route in the completed registry renders in all 4 locales with no id leakage and no untranslated English in zh-* locales.
  • `npx tsx scripts/check-i18n-gate.ts --check` exits 0 on a clean tree and exits non-zero for each of stale / missing / orphan / redundant / stale-human / I18N_ZHCN_STALE / I18N_REDUNDANT_OVERRIDE, and runs in CI with zero LLM calls and zero credentials.
  • Introducing an unknown message key fails `npm run typecheck` via the generated MessageKey union.
  • `npm run i18n:translate` run twice in a row makes zero model calls on the second run, and never overwrites an origin:"human" entry; the ollama model resolves from `I18N_OLLAMA_MODEL` (default qwen3:14b) and appears in no source file as a literal.
  • locales/en-GB.json and locales/zh-CN.overrides.json contain only divergent keys — the gate reports zero redundant entries and zero I18N_REDUNDANT_OVERRIDE.
  • locales/zh-CN.json is a FULL generated catalog with an entry for every zh-TW key, and `npm run i18n:zhcn` reproduces it byte-for-byte on a clean tree (the gate fails `I18N_ZHCN_STALE` otherwise) — so a zh-CN user can never be shown Traditional characters.
  • The runtime fallback chains are exactly en-GB→en-US, zh-TW→en-US and zh-CN→en-US; zh-TW appears nowhere in zh-CN's runtime resolution path.
  • Any literal-string lint rule that exists is warn-only and never fails CI (D2).
  • `npm run typecheck`, `npm run lint` and `npm test` are green, and no scripts/i18n module (including the opencc wrapper) is reachable from the app bundle.

Out of Scope

  • DB-seeded content: lib/seed.ts (~145 exercises), lib/curated-programs.ts, assets/data/foods.json — these are data rows, not UI chrome; localizing them needs a schema migration plus a per-row translation strategy keyed on stable seed ids, which is a separate project (see Phase 7 / T18; deferral confirmed by D5).
  • User-created data (custom exercise names, notes, template names) — never translated by design; it is the user's own text.
  • RTL layout support — none of the 4 target locales is RTL.
  • Locale-aware number/date/unit FORMATTING beyond what lib/format.ts already does; this plan localizes messages, not formatting policy. D3 confirms en-GB does not diverge on date/number phrasing.
  • App store listing metadata and F-Droid description translations.

Risk Flags

  • ROUTE-ORACLE GAP (highest risk to the 'verify all routes' goal): e2e/design-quality.spec.ts:28-78 registers only 22 non-onboarding routes (+3 onboarding), not the 27 stated in the brief, while app/ holds ~45 screen files. Roughly 20 routes — including all 7 app/settings/* screens and the whole session player — are currently invisible to the oracle. T3 must CLOSE this gap or Wave 8 will certify a false green.
  • GENERATED-ARTIFACT HAZARD (D4): locales/zh-CN.json is committed but machine-produced, so a well-meaning hand-edit is silently destroyed by the next regeneration. The `I18N_ZHCN_STALE` gate check is the only thing that makes this safe — if it is skipped, weakened, or the file is gitignored, zh-CN drift becomes invisible.
  • opencc tw2sp is not a total function: several Traditional forms map one-to-many, and the mainland-preferred word is not always the mechanical conversion. locales/zh-CN.overrides.json is the ONLY correction channel, so a missing override ships wrong-but-plausible Simplified copy rather than an obvious failure — this is harder to spot than an untranslated string.
  • zh-TW is a BUILD-time input to zh-CN, never a runtime fallback. If anyone re-adds zh-CN→zh-TW to the runtime chain, the original defect returns: any key missing from zh-CN would render TRADITIONAL characters to mainland users. T1's chain test and T16's DONOT are the guards.
  • zh-CN quality is downstream of zh-TW quality: because zh-CN is generated from T14's machine-translated zh-TW, any systematic error in zh-TW is faithfully converted into zh-CN for both audiences at once.
  • Hermes has no Intl: polyfills must be imported ABOVE `import "react-native-reanimated"` at app/_layout.tsx:1, or plural rules silently misbehave on device while passing in jest.
  • Babel plugin ordering: the lingui macro must precede react-native-reanimated/plugin, which must remain LAST in babel.config.js:5. Getting this wrong produces confusing worklet errors rather than i18n errors.
  • @lingui/core 6.6.0 is ESM and will break jest until added to transformIgnorePatterns (jest.config.js:100-102).
  • opencc-js must stay a DEV dependency reachable only from scripts/i18n/**; if it leaks into the app bundle it becomes an F-Droid/FOSS and bundle-size problem for a build-time-only concern.
  • Wave 4 is the largest blast radius in the plan (~1000-2000 strings over ~300 files). The batches are collision-safe ONLY because no agent writes locales/*.json — if any batch edits the catalog directly, expect merge conflicts and lost keys.
  • Wave 4 will churn many files at once and may trip the FTA complexity advisory and the coverage ratchet (jest.config.js:152-159) in .husky/pre-push; expect to re-baseline rather than to weaken the thresholds.
  • expo-localization returns zh-Hant-TW — resolution must use the explicit lookup map; a regex like /^zh/ will silently route Taiwan users to zh-CN.
  • Machine-translated zh-TW/zh-CN ships unreviewed unless a human pass is scheduled; origin:"machine" makes that reviewable later, but the first release will contain unvetted copy.
