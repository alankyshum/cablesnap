# Internationalisation (i18n)

This document describes how CableSnap's UI translation catalogs are authored,
generated, checked, and resolved at runtime.

## How to add a string

In JSX, import `Trans` from `@lingui/react/macro` and use an explicit static
ID:

```tsx
<Trans id="settings.example.title">Source text</Trans>
```

Outside React, import `t` from `@lingui/core/macro`:

```ts
t({ id: "settings.example.title", message: "Source text" });
```

IDs are dot-namespaced from the file path (for example,
`home.recent.empty`). The `id` must always be a static string literal. The
`message` may contain ICU placeholders such as `{count}`; that is the correct
way to interpolate a value. Do not make `message` a conditional or a string
concatenation: the Babel macro silently hoists those expressions into
positional placeholders. A gate rule rejects conditional or concatenated
messages so source text cannot accidentally leak into catalogs.

After adding or changing strings, use this pipeline:

1. `npm run i18n:codegen` regenerates the `MessageKey` union. This makes
   unknown message IDs fail typecheck.
2. `npx lingui extract` populates the catalogs. `locales/en-US.json` is the
   source of truth; its entry count changes whenever strings are extracted.
3. `npm run i18n:translate -- --locale zh-TW` translates missing or stale
   Traditional Chinese entries with local Ollama at zero cost. The model is
   selected with `I18N_OLLAMA_MODEL`.
4. `npm run i18n:zhcn` regenerates Simplified Chinese from Traditional
   Chinese, applying the Simplified Chinese overrides.
5. `npm run i18n:check` runs the offline gate.

Translation is always an explicit local step. CI never calls the translator.

## Catalog model

- **en-US** is the full source catalog and source of truth.
- **en-GB** is partial: it contains 74 entries, and an absent entry inherits
  from en-US. Its entries are hand-authored with `origin: "human"`.
- **zh-TW** is full and machine-translated.
- **zh-CN** is a full generated artifact. `npm run i18n:zhcn` applies OpenCC
  `tw2sp(zh-TW)` and merges `locales/zh-CN.overrides.json`; overrides win.

**Never hand-edit `locales/zh-CN.json`.** Edit
`locales/zh-CN.overrides.json` and regenerate it instead.

Runtime fallback chains are:

- en-GB → en-US
- zh-TW → en-US
- zh-CN → en-US

zh-TW is a build-time input to zh-CN only. It must never be part of zh-CN's
runtime fallback chain.

## The offline gate

`npm run i18n:check` is pure and offline. It reports these violation classes:

| Violation | What to do |
| --- | --- |
| `I18N_STALE` | Re-run `npx lingui extract`, then update the affected translation and its source hash; for zh-CN, regenerate it. |
| `I18N_MISSING_KEY` | Add the missing full-catalog entry, normally by running `npm run i18n:translate -- --locale zh-TW` or regenerating zh-CN. |
| `I18N_ORPHAN_KEY` | Remove the catalog entry or restore the source string, then run `npx lingui extract`. |
| `I18N_REDUNDANT` | Remove the partial-locale entry that exactly duplicates its inherited value. |
| `I18N_STALE_HUMAN` | Re-review the changed human translation, update its `message` and `srcHash`, and keep `origin: "human"`. |
| `I18N_ZHCN_STALE` | Run `npm run i18n:zhcn`; do not edit `locales/zh-CN.json` manually. |
 | `I18N_REDUNDANT_OVERRIDE` | Remove the override when it duplicates OpenCC output, or change it if the wording is deliberately pinned. |
| `I18N_UNTRANSLATED_ICU_BRANCH` | Translate English words in every plural/select branch body. Reviewed proper nouns, acronyms, and units use the shared branch-token allowlist. |
| `I18N_LOCALE_CODE_ECHO` | Replace a translation that is literally a locale code. |
| `I18N_UNTRANSLATED_CJK_LOCALE` | Add Chinese text to a CJK-locale translation that otherwise remains English. |
| `I18N_PLACEHOLDER_MISMATCH` | Preserve the source placeholder names exactly. |
| `I18N_CONDITIONAL_MESSAGE` | Move conditional/concatenated source copy into ICU message syntax. |
| `I18N_WRONG_SCRIPT` | Use Traditional characters in zh-TW and Simplified characters in zh-CN. |

The gate is deliberately offline and deterministic. Translation is never an
implicit CI operation; a developer must run the local translation command
explicitly when translated entries need to be created or refreshed.

## Entry metadata

An entry with `origin: "human"` is pinned: the translator never overwrites it.
`srcHash` records the source English message used for the entry. When that
English source changes, a mismatched `srcHash` marks the translation stale and
forces review. This applies to human entries as well as machine translations;
human entries additionally produce `I18N_STALE_HUMAN`.

## Deferred scope

The initial UI rollout intentionally excluded these seeded data collections:

- `lib/seed.ts`: approximately 56 Voltra exercise records.
- `lib/seed-community.ts`: approximately 89 community exercise records.
- Together: approximately 145 seeded exercises.
- `lib/curated-programs.ts`: curated programs.
- `assets/data/foods.json`: food data.

These are database/data content, not UI chrome. They are seeded into the user's
database, so translating them requires a data-migration strategy rather than a
catalog entry. A future task must decide the translated-data storage shape,
whether existing users receive a migration, how user edits and custom records
are preserved, how locale changes affect already-seeded records, and how the
data is reviewed and regenerated.

## Known quality caveat

zh-TW was machine-translated with the small local `qwen2.5vl:7b` model because
larger local models were unavailable. zh-CN is derived from zh-TW. Neither
catalog has had a native-speaker review pass. Native-speaker review remains an
open follow-up.
